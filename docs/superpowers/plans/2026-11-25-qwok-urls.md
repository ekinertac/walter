# qwok URLs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typing `qwok b2` in Walter lists qwok web apps; Tab completes the name, Enter opens the URL.

**Architecture:** A new `QwokIndex.swift` holds a pure parser and ranking for the `qwok list` table, and a loader that runs qwok in the background. `LauncherEngine.search` sends prefixed queries to it, next to the GitHub check. The existing `SearchResult.completion` handles Tab, and `.url` handles Enter and Cmd+C, so the panel controller does not change.

**Tech Stack:** Swift 5.9, AppKit, Foundation `Process`, Swift Testing. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-qwok-urls-design.md`

## Global Constraints

- macOS 13 minimum, no new dependencies, no change in qwok.
- Prefix setting: `[search] qwok_prefix`, default `"qwok"`, empty turns it off.
- qwok is searched in `/opt/homebrew/bin/qwok`, then `/usr/local/bin/qwok`. Both directories go at the front of the child's PATH.
- Memory only, no disk cache. No start/stop/status features.
- Every new file starts with a header block (responsibility, callers, dependencies, constraints). Comments explain why.
- File contents change only through Edit/Write.
- Commit only after Ekin asks.

## Review Focus

- qwok fails after an earlier success: the old list stays. Task 2.
- qwok prints warnings on stderr but exits 0: the list is used. Task 2.
- The panel opens again while a fetch runs: no second qwok process starts in parallel, and the list is fetched again afterwards. Task 2.
- `QWOK B2` and `qwok b2-browser ` (trailing space after the name) still match. Task 3.
- Both prefixes set to the same word: GitHub wins. Covered by the check order in Task 3, not by a unit test.

### Task 2: Loader

**Files:**
- Modify: `Walter/Sources/Walter/Launcher/QwokIndex.swift`
- Test: `Walter/Tests/WalterTests/QwokIndexTests.swift`

**Interfaces:**
- Consumes: `QwokApp`, `QwokList.parse` (Task 1).
- Produces: `final class QwokIndex` with
  - `enum State: Equatable { case ready([QwokApp]); case loading; case qwokMissing; case failed(String) }`
  - `private(set) var state: State` (starts as `.loading`)
  - `init(candidates: [String] = QwokIndex.defaultCandidates, onChange: @escaping () -> Void)`
  - `func invalidate()`: marks the list as old, does not start qwok
  - `func ensureFresh()`: starts one background fetch when the list is old and none is running
  - `static func environment(_ base: [String: String]) -> [String: String]`: PATH with the two directories in front

State is used on the main thread only; `Process` runs on a background queue. Read stdout and stderr before `waitUntilExit`, as in `GitHubIndex.run`. A fetch failure or a missing binary replaces the state only when it is not `.ready`. `onChange` is called only when `state` changed. `invalidate()` during a fetch must not be lost when the fetch ends.

- [ ] **Step 1: Write the failing tests.** Use `@MainActor` async tests, a temporary directory, and an executable shell script as the fake qwok. A helper polls `state` with `Task.sleep` for at most 5 s.
  - `environmentPutsBrewFirst`: `environment(["PATH": "/usr/bin", "HOME": "/h"])` gives PATH `/opt/homebrew/bin:/usr/local/bin:/usr/bin` and keeps `HOME`; without PATH it gives `/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin`.
  - `missingBinary`: `candidates: ["/nonexistent/qwok"]`, after `ensureFresh()` state is `.qwokMissing`.
  - `loadsListEvenWithStderrNoise`: script writes `warn` to stderr, prints one web row, exits 0; state becomes `.ready([that app])` and `onChange` ran once.
  - `failureShowsStderr`: script writes `boom` to stderr, exits 1; state becomes `.failed("boom")`.
  - `failureKeepsOldList`: succeed once, rewrite the script to exit 1, `invalidate()`, `ensureFresh()`; state is still `.ready` and the script ran twice (it appends a line to a counter file).
  - `noFetchUntilInvalidated`: after `.ready`, a second `ensureFresh()` does not run the script again.
  - `invalidateDuringFetch`: script sleeps 0.3 s; `ensureFresh()`, `invalidate()`, `ensureFresh()` gives 1 run at that moment; after it ends, `ensureFresh()` gives a second run.
- [ ] **Step 2:** Run `swift test --filter QwokIndex`. Expected: compile error, `QwokIndex` not found.
- [ ] **Step 3: Implement `QwokIndex`.** Repeat the small `Process` code from `GitHubIndex` (second use, not shared yet). If stderr is empty on failure, the message is `qwok exited with <code>`.
- [ ] **Step 4:** Run the same command. Expected: PASS.
